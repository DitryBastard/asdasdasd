# AI Переводчик

Локальный ИИ-переводчик технической документации с собственной базой переведённых
документов (translation memory). Модель запускается полностью локально через
Ollama — тексты никуда не уходят.

## Как это устроено

```
frontend/  React + TypeScript интерфейс (перевод, база переводов)
backend/   FastAPI сервис: RAG-пайплайн перевода + база переводов на Chroma
Ollama     локальный сервер, отдаёт LLM (перевод) и embedding-модель (поиск)
```

Схема запроса на перевод:

1. Текст режется на предложения (с учётом языка, включая русский).
2. Каждое предложение превращается в embedding через Ollama (`bge-m3`).
3. Embedding ищется в локальной базе (Chroma) среди уже переведённых пар того
   же направления перевода.
4. По совпадению принимается решение:
   - **≥ 98% схожести** — предложение уже есть в базе почти дословно,
     сохранённый перевод используется как есть, модель не вызывается вообще.
     В интерфейсе это подсвечивается зелёным как «точное совпадение из базы».
   - **75–98% схожести** — найденная пара передаётся модели как референс
     терминологии/стиля в промпте, но перевод всё равно генерирует модель.
     Подсвечивается жёлтым как «похоже на запись из базы», с процентом схожести.
   - **< 75%** — совпадений нет, обычный перевод моделью.
5. Готовые пары сентенций собираются обратно в текст с сохранением абзацев.

Это честная механика: LLM не даёт токен-левел доказательств, "что она взяла
из базы", поэтому подсветка показывает не более и не менее того, что реально
происходит — какое совпадение было найдено и как оно использовано.

## Требования

- **Ollama** (https://ollama.com) — локальный сервер моделей.
- **Python 3.11+**
- **Node.js 18+**
- Видеокарта с достаточным объёмом VRAM (тестировалось в расчёте на RTX 5090,
  32 ГБ) — сам backend GPU не использует, всю инференс-нагрузку несёт Ollama.

### Модели

```bash
# Модель перевода. Qwen2.5 хорошо переводит технические тексты и уверенно
# работает с русским. На RTX 5090 можно выбрать более крупную модель.
ollama pull qwen2.5:14b-instruct     # быстрее, ~9 ГБ VRAM в Q4 — вариант по умолчанию
ollama pull qwen2.5:32b-instruct     # заметно качественнее, ~20 ГБ VRAM в Q4 — рекомендуется на 5090

# Embedding-модель для поиска по базе переводов — многоязычная, хорошо
# работает с русским и техническими терминами.
ollama pull bge-m3
```

Если возьмёте `qwen2.5:32b-instruct` вместо модели по умолчанию, укажите её в
`backend/.env` (см. ниже).

## Быстрый старт

### 1. Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # при необходимости отредактируйте модель/пороги
uvicorn app.main:app --reload --port 8000
```

Убедитесь, что Ollama уже запущена (`ollama serve`, обычно поднимается
автоматически после установки).

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Откройте адрес, который выведет Vite (обычно http://localhost:5173). Dev-сервер
проксирует `/api/*` на backend (`localhost:8000`), поэтому CORS настраивать не
нужно.

В шапке интерфейса виден статус подключения к Ollama и количество записей в
базе — если Ollama не отвечает, там будет явное предупреждение.

## Наполнение базы переводов

Вкладка «База переводов» даёт два способа пополнения:

- **Пара документов** (.docx / .pdf / .txt) — загружаете оригинал и готовый
  перевод, backend сопоставляет абзацы по порядку следования и показывает
  таблицу пар для проверки. Пары можно отредактировать или удалить перед
  сохранением — это важно, потому что сопоставление позиционное (абзац N с
  абзацем N) и не проверяет, что абзацы действительно соответствуют друг
  другу по смыслу.
- **Ручное добавление** — быстро добавить одну пару термин/фраза → перевод,
  без файлов.

При сохранении пары каждый абзац дополнительно разбивается на предложения;
если количество предложений в оригинале и переводе совпадает, в базу
попадают более точные пары на уровне предложений (лучше для последующего
поиска), иначе — весь абзац целиком.

## Конфигурация (`backend/.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` | адрес Ollama |
| `OLLAMA_CHAT_MODEL` | `qwen2.5:14b-instruct` | модель перевода |
| `OLLAMA_EMBED_MODEL` | `bge-m3` | модель эмбеддингов |
| `CHROMA_PERSIST_DIR` | `./data/chroma` | где хранится база переводов на диске |
| `EXACT_MATCH_THRESHOLD` | `0.98` | порог "точного" совпадения |
| `FUZZY_MATCH_THRESHOLD` | `0.75` | порог "похожего" совпадения |
| `TOP_K_MATCHES` | `3` | сколько кандидатов рассматривать на предложение |
| `BATCH_SIZE` | `20` | сколько предложений уходит в модель за один запрос |
| `CORS_ORIGINS` | `http://localhost:5173` | разрешённые origin для API |

## Тесты

```bash
cd backend
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest
```

Тесты покрывают чистую логику (разбиение на предложения, классификацию
совпадений, разбор пронумерованных ответов модели, позиционное выравнивание
абзацев) и сквозную проверку API-маршрутов с подменённым Ollama-клиентом —
без обращения к реальной модели или GPU.

## Известные ограничения

- Выравнивание абзацев при загрузке пары документов позиционное (по номеру
  абзаца), без смыслового сопоставления — поэтому в интерфейсе есть шаг
  проверки перед сохранением.
- Извлечение текста из PDF работает по эвристике (разбиение по пустым
  строкам); для сложных многоколоночных макетов качество ниже, чем для .docx.
- Перевод возвращается как текст; исходное форматирование документа (стили,
  таблицы, изображения) не восстанавливается — на выходе обычный текст.
- Backend не проверялся с реальной Ollama и GPU в среде разработки (в этом
  окружении нет видеокарты) — вся сетевая логика проверена тестами с
  подменённым клиентом, но перед первым реальным использованием стоит
  прогнать пару переводов вручную и свериться с ожиданиями.
